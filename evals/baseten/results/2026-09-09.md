## Comparison protocol

All three configurations use `zai-org/GLM-5.2-Fast`, the same prompts/assertions within each iteration, and both the docs and management MCP servers. The no-skill baseline has the same built-in Claude Code skills as the skill arms. One worker per configuration was used; cross-process fixture locks prevent simultaneous resets and mutations of the same model.

The skill snapshots were frozen outside the repository. The runner records model, provider, skill, rubric and fixture hashes. The [May benchmark statistics](2026-05-26.md) remain unchanged. [Curated statistics for all 69 executions](2026-09-09-stats.jsonl) identify the iteration, configuration, scores, usage, and explicit skill invocation. Sanitized raw artifacts and HTML reviewers are retained outside the repository in `/Users/baseten/my-wiki/baseten-skills-workspace/2026-09-09/iteration-1` and `iteration-2`. Temporary credential homes were removed.

The comparison command in [the eval guide](../README.md) validated complete task sets and matching provenance. Use each archived iteration's `evals.json` when reproducing its comparison; the current suite contains the corrected assertions. The aggregate pass rate weights tasks equally. The report lists weighted assertion scores separately. Token counts and duration come from executor events and exclude grading. Provider billing cost is unavailable. Paired bootstrap intervals across tasks do not estimate within-task randomness with one repetition.

The live fixture reset restores the current broken deployment but retains deployment history and counters. In task 30, the June executor rolled back to a good deployment created by the refreshed executor, then treated existing counters as verification. The grader rejected that verification, but the differing histories still confound the operational comparison. The reset now also preserves the fixture's actual name in its embedded configuration; during the initial run a stale name caused a temporary duplicate, which the executor deleted (independently confirmed by HTTP 404).

The model explicitly invoked the Baseten skill in **7/21 refreshed** and **6/21 previous** executions. This measures availability plus activation behavior, not guaranteed use of the instructions. Direct file reads are not included in that invocation count; the failed refreshed cold-start case used only MCP reads and did not invoke the skill.

A spot check found an invalid Hugging Face revision in a passing output. GPU/engine-choice assertions can also penalize potentially valid alternatives. Scores measure rubric compliance, not demonstrated deployment correctness or measured throughput. The same model executes and grades, which can compound blind spots.
