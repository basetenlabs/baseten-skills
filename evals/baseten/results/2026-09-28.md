## 65: train-loops-managed-client

Prompt:

> My Loops client needs to run unattended because my laptop sleeps. What Baseten command should I use to package this directory and run `uv run python train.py`, while reusing my current Baseten CLI workspace credentials? Do not execute the command.

Assertions:

- Uses `baseten loops exec --with-uv --tail -- uv run python train.py` and does not substitute raw `truss loops exec`, `b10 run`, or a nonexistent command.
- Explains that the command packages the current directory, runs the client as a managed Training Job, and forwards the active Baseten CLI workspace credentials.
- Does not execute the command or create billable resources.

## 66: train-loops-checkpoint-deploy-safety

Prompt:

> I have a Loops sampler checkpoint and want to deploy it through an agent. Which Baseten API or MCP operation should the agent choose, and what safety checks should it mention around authorization, billing, retries, and trainer checkpoints? Do not deploy anything.

Assertions:

- Names either the `deploy_loops_checkpoint` MCP tool or `POST /v1/loops/checkpoints/deploy`, rather than inventing a generic deployment operation.
- Says to confirm the user's intent before creating billable resources and explains that the service authorizes access to the checkpoint's team.
- States that only sampler-target checkpoints deploy and trainer-target checkpoints contain training state.
- States that deployment is not idempotent and that an uncertain result must be inspected before retrying to avoid duplicate deployments.
- Does not execute a deployment or another billable operation.

| No skill | 3/5 (60%) | 83,370 / 1,168 | 17.5s | Covered billing, retries, and checkpoint type, but did not name the exact API or MCP operation or team authorization behavior. |
| Updated skill | 5/5 (100%) | 55,335 / 789 | 11.8s | Named the endpoint and covered confirmation, team ownership, sampler-only deployment, and ambiguous-result handling. |

The updated skill improved this single targeted sample by 40 percentage points. One repetition does not establish repeatability or full-suite quality.

## Takeaways

- Make `baseten loops exec` the only recommended command for managed Loops client execution. It preserves the active Baseten CLI workspace context.
- Keep checkpoint deployment guidance concrete: name the REST endpoint or MCP tool, require confirmation, distinguish sampler and trainer checkpoints, and forbid blind retries.
- Keep the skill PR gated until the Baseten CLI command, Management API endpoint, MCP tool, and linked docs are published.
